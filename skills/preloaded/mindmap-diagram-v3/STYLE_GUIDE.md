# XMind-Style Mind Map Style Guide

本指南描述 skill 优化的脑图视觉风格与节点写作规范。

## 视觉目标

类似精修后的 XMind 导出效果：

- 深色画布
- 亮色中心主题
- 彩虹分支线
- 圆角节点
- 紧凑层级
- 结构周围大量留白
- 整洁、适合汇报的组织方式

## 内容风格

### 中心主题
使用简短、概括性的标题。

好的示例：
- 中期小结与工作规划
- 项目复盘与后续计划
- 知识体系总览

不好的示例：
- 关于2024年上半年工作总结及下半年工作计划的汇报（太长）
- 工作相关（太模糊）

### 一级分支
使用汇报的主要维度，保持同级抽象层次一致。

常用模式：
- 总体小结
- 工作成果
- 存在问题
- 后续规划

### 二级分支
使用平行的子维度。

示例：
- 关键成果
- 模型部署
- 模型量化
- 技术跟踪

### 三级分支
使用证据、示例或数据指标。

示例：
- 显存下降 46.9%
- 延迟下降 23.1%
- 业务反馈良好

## 节点写作规范

好的节点文本：
- 简短（建议 ≤5 个词或 ≤15 个中文字）
- 具体明确
- 同级措辞平行
- 动作导向（流程节点用动词，分类节点用名词）

不好的节点文本：
- 长句子（"我们在第一季度完成了模型部署并且取得了很好的效果"）
- 混合逻辑（一个节点包含多个观点）
- 模糊表达（"相关事项"、"其他"）
- 冗长解释

## 分支塑形规则

1. 最重要的分支靠近中心放置
2. 同级分支保持相近长度（节点数和深度）
3. 避免某分支远深于其他分支，除非确实复杂
4. 默认 3 层深度；4 层仅在必要时使用
5. 将重复细节合并为一个证据节点
6. 超过 7 个主要节点时拆分为多张图

## 连线风格规则

1. 主路径使用实线箭头 `-->`
2. 反馈/回退使用虚线箭头 `-.->`
3. 分支标注语义（如 `|main_flow|`、`|branch_out|`）
4. 避免无意义的装饰性连线

## 各图类型风格要点

### 脑图
- 中心主题 → 4-6 个一级分支 → 每分支 2-4 个二级 → 按需三级
- 一级分支按重要性从右上角顺时针排列

### 流程图
- 起止节点用圆角矩形 `([Start])` / `([End])`
- 处理节点用矩形 `[Process]`
- 判断节点用菱形 `{Decision}`
- 主路径从上到下（TD），跨页面流程从左到右（LR）

### 架构图
- 方向从左到右（LR）
- 外部系统在左，核心在中间，存储在右
- 同层模块对齐

### 泳道图
- 每个角色/部门一个 subgraph
- 跨泳道连线标注交互语义

### 时间线
- 从上到下按时间排列
- 每个节点标注时间 + 事件
- 关键里程碑加粗

## 常用汇报结构模板

工作总结类：
- 总体小结
- 履行职责与工作任务
- 不足之处与改进措施
- 今后工作打算

项目复盘类：
- 项目背景与目标
- 执行过程与关键节点
- 成果与数据
- 经验教训
- 后续优化

知识体系类：
- 核心概念
- 技术栈/工具
- 应用场景
- 学习路径
- 实践案例

## 图片输出视觉规范

### 渲染参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 画布宽度 | 1600px | 保证清晰度 |
| 背景色 | 白色 | 通用兼容 |
| 字体 | Arial / Helvetica | 跨平台显示一致 |
| 格式 | PNG（默认）/ SVG（矢量） | PNG 用于查看/分享，SVG 用于缩放 |

### 各图类型推荐样式

| 图类型 | 推荐主题 | 方向 | 特殊设置 |
|--------|----------|------|----------|
| 脑图 | default | 放射状 | useMaxWidth: true |
| 流程图 | default | TD（纵向） | curve: basis |
| 架构图 | default | LR（横向） | curve: basis |
| 泳道图 | default | TD | subgraph 样式 |
| 时间线 | default | 纵向 | useMaxWidth: true |

### 图片质量检查

渲染图片后检查：
1. 文字是否清晰可读，无截断
2. 节点之间是否重叠
3. 中文是否正常显示（无方块/乱码）
4. 整体布局是否对称、平衡
5. 画布是否有过多空白（留白适中）

### 源文件编辑提示

修改源文件时的注意事项：
1. 修改 .mmd 文件后需重新渲染图片
2. 不要直接修改 PNG/SVG 文件
3. 保持源文件中的缩进一致（2 空格）
4. 中文节点不需要加引号
5. 特殊字符用 HTML 实体（如 `&amp;` 代替 `&`）
