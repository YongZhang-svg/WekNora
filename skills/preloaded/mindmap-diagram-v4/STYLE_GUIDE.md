# Diagram Style Guide

本指南描述 skill 的图形风格与节点写作规范。

## 视觉目标

- 结构清晰
- 留白充足
- 自动布局自然
- 适合汇报与文档插入
- 默认离线可渲染

## 总体风格原则

1. **优先可读性**，再考虑装饰性
2. **优先自动布局**，减少人工排版成本
3. **优先矢量输出**，便于缩放
4. **优先短标签**，减少拥挤和重叠

## 脑图风格

脑图默认使用 Markdown 大纲生成 Graphviz radial 图，视觉上尽量接近精修后的思维导图。

### 内容规则

- 中心主题短而明确
- 一级分支控制在 4–6 个
- 二级分支保持同级平行
- 三级分支只放细节或证据
- 节点文本建议不超过 15 个中文字

### 视觉规则

- 根节点高亮，其他节点保持轻量
- 一级分支使用区分度更高的颜色
- 子节点颜色逐层变浅
- 节点使用圆角矩形
- 线条细而清晰
- 整体居中，避免某一侧过重

### 推荐输出

- 首选：SVG
- 次选：PNG
- 预览：HTML

## Graphviz 风格

适合复杂层级、依赖关系、树形结构、径向布局。

### 推荐参数

- `layout=twopi`：适合脑图 / 放射状结构
- `splines=true`：减少折线感
- `overlap=false`：避免重叠
- `pad=0.25`：增加留白
- `nodesep` / `ranksep`：控制间距

### 节点样式建议

- `shape=box`
- `style="rounded,filled"`
- `penwidth=1.2`
- `fontsize=13`
- `fontname` 使用本地可用中文字体

## D2 风格

适合架构图、流程图、模块依赖图。

### 推荐原则

- 尽量短句
- 节点统一命名风格
- 模块之间关系明确
- 不把解释性长句塞进节点

### 适用情况

- 需要自动避让和紧凑布局
- 节点多、连线多、交叉多
- Mermaid 画面太挤时

## Mermaid 风格

仅作为兼容与降级方案使用。

- 节点少时可直接用
- 时序图、简单流程图仍适合
- 复杂图优先切换到 D2 / Graphviz

## 写作规范

### 好的节点文本

- 简短
- 具体
- 同级平行
- 一个节点只表达一个意思

### 不好的节点文本

- 长句子
- 混合多个观点
- 模糊词汇，如“其他”“相关事项”
- 同级节点一个是概念，一个是例子

## 图类型风格要点

### 脑图
- 根节点居中
- 一级分支放大权重
- 先总后分
- 少用重复词

### 流程图
- 起点、判断、处理、终点层次清晰
- 主路径尽量单方向推进
- 回路用虚线表达

### 架构图
- 外部系统在外侧
- 核心服务在中心
- 存储和依赖靠边放

### 泳道图
- 每个角色一个区域
- 跨区域交互少而明确

### 时间线
- 按时间顺序排列
- 关键节点加粗
- 每个时间点只放一个核心事件

## 图片质量检查

渲染后检查：

1. 文字是否清晰
2. 节点是否重叠
3. 中文是否正常显示
4. 画面是否过于拥挤
5. 是否适合直接放进汇报材料

## 源文件编辑提示

1. 修改源文件后重新渲染
2. 保持缩进一致
3. 节点文本尽量短
4. 避免在节点里塞太多解释句
5. 尽量使用结构化表达而不是段落式表达
